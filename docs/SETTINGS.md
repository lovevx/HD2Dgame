# 设置页（画面 / 声音 / 游玩 / 按键）

> 落地日期：**2026-09-23**　状态：✅ 已落地（`tools/validate_settings.gd` 84 项断言全绿）
> 入口：**主菜单 →「设 置」** 与 **游戏内 Esc 菜单 →「设 置 · 画面 / 声音 / 按键」**
> 正本：`autoload/game_settings.gd`（数据 + 落盘 + 即时套用）· `scripts/ui/settings_panel.gd`（界面 + 改键捕获）

本文回答三件事：**页面上有什么**、**每一项改的是哪个消费方**、**哪些还没做**。

---

## 1. 为什么偏好与进度分开存

| 文件 | 装什么 | 谁写 | 什么时候会被清 |
|---|---|---|---|
| `user://save.cfg` | 进度（契约者、乐园币、阶段、背包） | `GameState` | 「开始新游戏」/ `reset_progress()` |
| `user://settings.cfg` | **偏好**（画面 / 声音 / 游玩 / 按键） | `GameSettings` | 只有玩家自己点「恢复默认」 |

`reset_progress()` **不碰** `settings.cfg` —— 换档、重开、删档都不该把音量与键位重置回默认。

写盘策略比存档简单：偏好档损坏最多回到内置默认，不会丢进度，所以**不做**「临时档 + rename + `.bak`」
那套原子替换，直接写并在失败时 `push_error`。逐项**读时校验**：手改过的档、旧版本残留、
超范围的值都会被夹到有效区间或退回内置默认（`load_settings()` 里逐项 `clampi` / `clampf` / 档位白名单）。

## 2. 页面内容与作用点

面板是左侧四个分页 + 右侧内容（`layer 45`，比任务档案的 40 更高）。每一行改完**立刻生效并落盘**，
不需要重启，也没有「应用」按钮。

### 2.1 画面

| 项 | 档位 | 默认 | 作用点 |
|---|---|---|---|
| 窗口模式 | 窗口 / 全屏（独占）/ 无边框全屏 | 窗口 | `DisplayServer.window_set_mode` |
| 分辨率 | 1280×720 / 1600×900 / 1920×1080 / 2560×1440 | 1920×1080 | `window_set_size` + 按屏幕居中，**仅窗口模式**（全屏下这一行置灰） |
| 垂直同步 | 开 / 关 | 开 | `window_set_vsync_mode` |
| 帧率上限 | 60 / 90 / 120 / 144 / 不限制 | 60 | `Engine.max_fps` |

### 2.2 声音

| 项 | 范围 | 默认 | 作用点 |
|---|---|---|---|
| 主音量 | 0~100 | 100 | Master 总线 `volume_db`（0 直接静音，不写 `-inf`） |
| 音效音量 | 0~100 | 100 | `SFX` 总线，定义在 `res://default_bus_layout.tres` |

`SFX` 总线是本轮新加的唯一非 Master 总线。消费方：`scripts/player/dash_fx.gd` 的三个剃音效
（`Prefs.SFX_BUS`）。总线名只有一份正本（`data/prefs.gd`），面板与播放器都读它。
**当前版本没有背景音乐**，所以主音量实际管的是整体输出；将来接 BGM 时加一条 `Music` 总线即可，
面板结构不用改。

### 2.3 游玩

| 项 | 范围 | 默认 | 消费方（读的是内存里的实时值） |
|---|---|---|---|
| 镜头灵敏度 | 0.4× ~ 2.0× | 1.0× | `scripts/world/camera_orbit_controls.gd`：`ORBIT_SENSITIVITY × 倍率`，中键拖动时现读 |
| 镜头上下反转 | 关 / 开 | 关 | 同上，只翻 pitch 方向（yaw 不变，滚轮步长不变） |
| 过场镜头震动 | 开 / 关 | 开 | `scripts/main/cinematic.gd` 的 `_draw_city()`：只掐震动，推近与缩放照旧 |
| 鼠标光标 | 游戏内剑刃光标 / 系统光标 | 游戏内 | `scripts/ui/hud.gd` 的 `wants_game_cursor()` |

「游玩」这几项**没有 `apply` 步骤**：消费方用的时候即时来读，所以改完下一帧就生效，
也不会被切场景覆盖回旧值。面板打开时一律交还系统光标，与光标样式无关（否则点不到按钮）。

### 2.4 按键

- 可改键动作 20 个，分组列在 `scripts/ui/key_bindings.gd` 的 `REBINDABLE`。点右侧键位格 → 按新键 → 完成。
- **冲突处理：对调**。新键已被别的动作占用时，把对方那一个事件摘掉；摘完对方一个键都不剩，
  就把自己的旧键让给它，并把这次对调也写进覆盖表（否则重启后对方被工程默认键顶回来，两个动作撞在同一个键上）。
- **恢复默认键位**：`InputMap.load_from_project_settings()` + 清空覆盖表。默认值的正本是
  `project.godot` 的 `[input]`，代码里不再抄第二份。
- **改不了的**：鼠标中键拖动取景、滚轮推拉 —— 它们是相机代码里硬判的 `MOUSE_BUTTON_*`，不是 InputMap 动作。
  F1 说明面板里如实标注为手势，不进改键表。
- 本轮顺带把两个**玩家会按、却不是 InputMap 动作**的键补成了动作，否则改键表会有洞：
  `shoot`（燧发枪，默认鼠标右键，原 `player.gd` 里硬判 `MOUSE_BUTTON_RIGHT`）、
  `kick`（直踹，默认 **`E`** —— 2026-09-23 由 `K` 改为 `E`，原 `E` 的傲歌对调为 `K`；此前原 `player.gd` 里硬判 `KEY_K`，且连 F1 说明都没列）。

## 3. 键名文案不会再走偏

改动前：底部提示条与 F1 说明里的键名是**写死的字符串**，改键后会立刻变成假话。
现在键名只有一份来源：

- `key_bindings.gd` 的两张表（`HINT_ITEMS` / `GROUPS` / `CAMPAIGN_GUIDE_LINES`）只留「这个键干什么」的短语，
  键名一律由 `keys_of()` / `key_text()` 从 `InputMap` 现读。
- `GameSettings.changed("keys")` → `hud._on_settings_changed()` 重算底部提示条与 F1 说明的键名列。
- 顺带修掉了旧文案里的两处失实：「左键三连击」（早已是单段斜劈）、「Shift 闪避」（剃是空格，Shift 是废弃的 `run`）。
- **范围扩大（09-23）**：不止上面两张表 —— 教程目标（`data/quest_log.gd`）、向导对话与关卡目标（`campaign.gd`）、
  Boss 提示（`boss_director.gd`）、战斗状态栏（`hud.gd`）、服务点与宝箱的贴底提示（`harbor_service.gd` / `scene_chest.gd`）、
  眩晕处决提示（`player.gd`）、选关操作说明（`level_select.gd`）里的键名也一律改成现读，写死的键名已经没有了。

## 4. 接入点

| 入口 | 位置 | 行为 |
|---|---|---|
| 主菜单 | `scripts/main/main_menu.gd`，「关卡调试」与「退出游戏」之间 | 面板挂在主菜单自己身上（主菜单没有 HUD） |
| 游戏内 | `scripts/ui/hud.gd` 的 Esc 菜单 | 点「设置」时先把 Esc 菜单收起，关掉设置后按 Esc 回到菜单 |
| 模态语义 | `hud.is_modal_open()` 计入 `_settings_open()` | 战役模式随之冻结玩家与敌人；相机不吃滚轮；系统光标交还 |
| 关闭 | 「返 回」按钮 / Esc | Esc 有两条路：HUD 的 `open_menu` 路由，以及面板自己 `_input` 里的兜底（玩家把 `open_menu` 改走之后仍关得掉） |

设置面板与其它面板的输入约定不同，它**自己吃两种输入**：改键捕获期间（拦「按下的任意键」）与
Esc 兜底。两处都在 `settings_panel.gd` 里就地注释了理由；其余情况不消费输入，交给 HUD 统一路由。

## 5. 校验与截图

```bash
# 单跑
godot --headless --path . --script res://tools/validate_settings.gd
# 或进套件
tools/run_regressions.sh validate_settings

# 视觉检查（必须带渲染，不加 --headless）：四个分页各截一张到 .tmp_preview/settings/
godot --path . --script res://tools/capture_settings.gd
```

覆盖四段（共 84 项断言，全绿）：

1. **设置档**：非法值兜底（窗口模式 9 → 夹取、帧率 37 → 60、分辨率不在档位 → 回默认、音量 9999 → 100、
   灵敏度 99 → 夹到上限）、档缺失时保留内存值、写入/读回往返（含按键覆盖表）。
2. **作用点**：`Engine.max_fps` 真的被写、Master/SFX 两条总线的 dB 与静音、`1.0× / 2.0× / 反转` 三种
   灵敏度下机位 `yaw`/`pitch` 的实际增量、`Prefs` 按路径取到的就是 `GameSettings`。
3. **按键**：改键写入 InputMap、冲突对调（含**对调结果落盘**）、滚轮不可绑定、
   清空覆盖表 / 恢复默认 / 重启读回三条路径、提示条文案随改键变化。
4. **面板接入**：主菜单入口与四个分页的实际行内容、改键捕获全流程（进入捕获 → 按键落定 → Esc 只取消）、
   HUD Esc 菜单入口、开设置后的模态冻结 / 相机让出滚轮 / 光标交还、剃音效确实挂在 SFX 总线上。

> **可证伪性**（本项目约定：跑不出失败的断言等于没有断言）。已实测三处故意打断后转红：
> 摘掉 `GameSettings.changed` 连接 → 「改键后 HUD 提示条立即跟着变」FAIL；
> 让 `_sensitivity_scale()` 恒返回 1.0 → 「2.0× 是基准的两倍」FAIL；
> 去掉 `dash_fx` 的 `audio.bus` → 「3 个音效播放器都挂在 SFX 总线上」FAIL（实测 `[Master, Master, Master]`）。

## 6. 未做与边界（明确记录，不是"忘了"）

| 项 | 现状 |
|---|---|
| 背景音乐 / 音乐音量 | 工程里还没有任何 BGM，所以只有主音量 + 音效音量两条 |

| 触屏键盘、辅助功能（色盲模式等） | 未做 |
| 删除进度 | 仍在主菜单的「开始新游戏」（`reset_progress()`），没有进设置页 |
