# 战斗系统改版方案：即时野战 + 回合指令战（轨迹式简化版）

状态：**待确认** · 起草：2026-09-20
参照系：《空之轨迹 the 1st》（2025 重制）/《黎之轨迹》的双形态战斗，按本项目体量做减法。

---

## 1. 背景与目标

现有实时动作战斗（`player.gd` 三段连击/闪避/拼刀 + `enemy.gd` 红圈预警 AI）对帧序列图的消耗是
**每动作 8 帧图集 × 8 方向（画 5 镜 3）= 40 帧/动作**，战斗部分已 280 帧，且每个新技能还要再画 40 帧。
代码中已出现复用妥协：环断复用三段挥刀帧、傲歌复用防御姿态帧、影刺无动画。

改版目标：

1. 战斗动画从"8 方向"降为"战斗画面单方向"，新技能不再新增帧序列（改用程序化特效表达）。
2. 保留探索玩法（八方向行走/待机、轨道相机、港口场景全部不动）。
3. 数值层（六维属性、装备/强化/耐久、技能数值公式）**原样继承**，不改表。

## 2. 参照系拆解与简化原则

轨迹系双形态的完整机制 → 本项目的取舍：

| 轨迹系机制 | 取舍 | 理由 |
|---|---|---|
| 野战即时战斗（普攻/闪避/战技攒眩晕） | **保留，精简** | 复用已画完的 8 方向攻击/闪避帧，美术零新增；跑图不清怪太憋闷 |
| 眩晕条 → 切回合 + 先手优势 | **保留（核心联动）** | 这是双形态的粘合剂，实现便宜 |
| Boss/精英强制回合战 | **保留** | 现有 boss_director 关卡直接挂"强制回合"标记 |
| AT 顺序栏 + AT 奖励/抢夺 | **只保留顺序栏**，砍奖励/抢夺 | 敏捷→先攻是六维现成的映射，随机奖励留给后续扩展 |
| 回合内走位（射程/侧背击加成） | **保留轻量版** | 场景内遭遇战本来就有 3D 场地，走位复用八方向行走帧；侧击 +10% / 背击 +25% 只是一个 dot 判断 |
| 魔法吟唱时间 | 砍（战技即发动） | 只有一个可操作角色，吟唱条徒增等待 |
| BP 勇气点 / 连携 / 合击 / LINK | 砍 | 目前单人无队友，等加入伙伴再议 |
| 完美闪避回蓄力 | 保留 | 已有 dodge 帧和无敌帧逻辑，只加"完美闪避→眩晕条奖励" |

## 3. 总体流程

```
探索（现状不变，轨道相机/八方向行走）
  │  遭遇敌人（白盒模型在场巡逻）
  ▼
┌─────────────── 即时野战 ───────────────┐
│ 普攻（三段精简为两段）/ 闪避 / 战技·斩铁 │
│ 命中 → 积累敌人眩晕条（头顶黄条）        │
│ 杂鱼眩晕 → 走近处决 = 直接击杀           │
│ 精英眩晕 → 攻击眩晕目标                  │
└──────────────┬───────────────────────┘
               │ 切换（眩晕触发 / Boss 强制）
               ▼
┌─────────────── 回合指令战（场景内，不切场景）─┐
│ 镜头切战斗运镜（固定俯角环绕战团）            │
│ AT 顺序条：敏捷排序轮动                       │
│ 我方回合：先移动（限移动力）→ 一条指令         │
│   攻击 / 战技 / 道具 / 防御 / 逃跑            │
│ 敌人回合：接近→攻击（现有数值档）             │
│ 胜利 → 掉落结算（equipment_drop 现有）        │
└──────────────────────────────────────────┘
```

## 4. 即时野战设计

- **保留**：移动、普攻（三段连击精简为两段，复用现有 attack 帧图集前两段）、闪避（含现有无敌帧；
  完美闪避 = 敌人出手瞬间闪避成功 → 所积眩晕翻倍）、战场技「斩铁」（蓄力 1 段释放，高眩晕值，
  复用现有第三段挥击帧 + 程序化剑气特效）。
- **删除**：拼刀（回合化后无意义）、猎魔开关（转为对能量敌的被动：战技对能量型 +15% 真伤，沿用
  `has_energy` 判定）、燧发枪/炸弹/药水的即时期使用（全部挪进回合战指令）。
- **眩晕条**：普攻每 hit +8，斩铁 +25，完美闪避所积翻倍；满 100 进眩晕态（头顶黄条常亮 + 白盒
  模型低头晃悠，代码驱动）。眩晕敌人被普攻命中：杂鱼直接处决击杀；精英/Boss 触发回合战且我方
  先手、该敌晕 1 回合。
- 野战伤害维持现有数值（不做轨迹式的"刮痧"惩罚），小怪本来 1~2 刀死。

## 5. 回合指令战设计

- **场地**：不切场景。触发点为圆心，取半径 8 m 的战斗圈，圈内敌人与玩家入战；战斗圈边缘立
  半透明结界网格（程序化，暗示活动边界），不能走出圈外。
- **AT 顺序条**：屏上方一条水平序列，按敏捷降序排（同敏捷随机微扰）；轮动无插入回合、无 AT 奖励。
  顺序栏显示敌人下一次行动意图图标（普攻/技能），沿用现有红圈预警的"可读性"思路。
- **我方回合 = 移动 + 指令**：
  - 移动力 = `3.0 + (敏捷 − 5) × 0.2` m，八方向行走帧直接复用，步进式（不走满也可停在原地）。
  - 指令菜单（参照 `shop_panel.gd` 的面板模式）：**攻击 / 战技 / 道具 / 防御 / 逃跑**。
- **攻击**：射程 = 武器 reach（近战 2.5 m / 燧发枪 9 m），扇形/圆形判定沿用现有 cone 逻辑换算。
  侧击 +10%、背击 +25%（dot 判断敌人白盒朝向，敌人本来就有 `_face_target`）。
- **战技**（数值沿用 `data/combat_skills.gd`，MP 沿用现有）：

| 指令 | 原技能 | 回合化改法 | 表现 |
|---|---|---|---|
| 剑气·断空 | sword_wave | 远程直线 12 m，穿透 | 现有 SwordWave 弹体 + cast 帧 |
| 环断 | ring | 自身边长 5 m 方形 AoE | 现有环冲击波特效原样复用 |
| 影刺 | shadow_stab | 突进到目标身前 + 高伤，不再要求先手标记 | 影刺尖刺特效 + 位移 |
| 傲歌 | shield | 自身减伤 50% 持续 2 回合（吸收量转固定减伤） | 现有护盾球 |
| 青钢影 | hunter | 本回合攻击对能量型附加真伤（改为主动增益 3 回合，CD 5） | 角色发光 tint，代码实现 |
| 燧发枪 | flintlock | 远程 9 m 单体，耗弹药 | 枪口闪光，程序化 |
| 炼金炸弹 | bomb | 指定圈内地块放置，下回合起敌人经过/回合末引爆 AoE | 现有 bomb.tscn |

- **防御**：本回合受伤 −75%，且被近战命中时 30% 概率"弹反"（弹反 = 敌人下次行动延后一轮）——
  这是拼刀机制在回合制的转生，不耗美术。
- **逃跑**：敏捷对抗（我方敏捷 + d10 vs 敌方平均敏捷 + d10），成功脱离野战状态，失败浪费一回合。
- **敌人回合**：沿用 `enemy.gd` 的数值档（hp/speed/damage/reach），AI 极简：不在射程 → 朝目标
  移动（消耗与玩家同规则的移动力）；在射程 → 攻击；精英按冷却放技能（野猪冲撞 = 直线突进等，
  复用现有 windup 数值改为"意图图标"展示）。
- **胜负**：敌方全灭 → 掉落/经验结算（equipment_drop 现有流程）；玩家 HP 归零 → 现有死亡流程；
  战斗中被打出眩晕 → 可直接处决玩家？不做，保持 HP 结算。

## 6. 数值迁移映射

| 现有系统 | 回合制去向 |
|---|---|
| 六维属性（data/attributes.gd） | 全保留；敏捷新增两个用途：AT 先攻排序、移动力 |
| 武器区间双 roll（_roll_range_damage） | 原样作为每次攻击/战技的伤害 roll |
| 力量倍率 str_atk_coef / 刀术训练 | 原样 |
| 护甲减免 + 肉体修正（§4.2 结算链） | 原样，落在防御指令与敌方攻击结算上 |
| 装备耐久（击杀扣耐久 kill_dur / 受击扣护甲） | 原样：击杀判定照旧，受击扣护甲改为"每次被命中扣 1" |
| MP 回蓝（每秒 regen / 命中回蓝） | 改为：每经过一整轮 +5% 最大 MP |
| combo_window / attack_cd / dodge_cooldown | 删除（实时参数）；技能 CD 改为"冷却 N 回合" |
| 拼刀 CLASH_* | 转生为防御指令的弹反 |
| 敌人 windup（前摇秒数） | 转生为 AT 栏意图预告（显示该敌下回合将攻击） |

## 8. 技术实现路径

- 新模块 `scripts/battle/`：
  - `battle_controller.gd`：回合状态机（遭遇→顺序→行动→结算→胜负），挂在战场节点。
  - `battle_unit.gd`：玩家/敌人统一封装（HP/MP/移动力/眩晕/意图）。
  - `battle_menu.gd` + `order_bar.gd`：指令面板与 AT 栏（Control 层，参照 shop_panel/hud 模式）。
  - `stun_gauge.gd`：敌人头顶眩晕条（Label3D 或程序化 mesh，同血量标签做法）。
- 改动面：
  - `player.gd`：增加 `battle_mode` 门闩——回合战中实时输入（attack/dodge/技能键）被控制器接管，
    探索输入照旧；三段连击保留两段。
  - `enemy.gd`：加巡逻态（野战慢速游荡）+ 眩晕条；回合战中的移动/攻击由 controller 驱动。
  - 遭遇触发：`wave_spawner.gd` 改造为 `encounter_zone`（接触/眩晕触发），Boss 关卡挂强制回合标记。
  - 相机：战斗时切固定战斗运镜（复用 `camera_orbit_controls` 的锚点，锁定俯角自动缓动，不出轨道控制）。
- 回归：`tools/validate_battle.gd` 无头校验——顺序排序正确性、伤害结算链（双 roll/减伤/背击加成）、
  先手优势、胜负流转、战斗圈禁出。既有 `validate_*` 管线并行不悖。
- 文档同步：`GDD.md`、`COMBAT_SYSTEM.md` 增补回合制章节并标注动作制章节状态。

### A.2 新造型 sheet（`新版动作/`）：一个块 = 完整 8 方向

`跑步动画.png` / `攻击动画.png` / `受击动画.png` / `闪避动画.png`，各 4736×2688。

**布局（作者确认 + 2026-09-20 实测校正）**：一张 sheet 含 3 个块（行组，块间有细分隔线）。
**每个块 = 3 个子行 × 4 个列组**；**一个列组 = 一整套 8 方向**（上排 3 个 / 中排 2 个 / 下排 3 个），
**4 个列组 = 4 帧**。所以：

| 排 | 每组张数 | 方向（组内左→右） |
|---|---|---|
| 上排 | 3 | down_left / down / down_right |
| 中排 | 2 | left / right |
| 下排 | 3 | up_left / up / up_right |

- 一行 = 4 个列组 → 每个方向一行出 4 帧；3 个块 × 4 = **每方向 12 帧**（跑步最后一块只有 3 个列组 → 11 帧）。
- 判定列组的依据：**行内第 3 / 6 / 9 个间隙明显更大**（待机上排 322px vs 普通 277px；
  中排第 2 / 4 / 6 个更大：695px vs 333px）。
- ⚠️ **踩过的坑**：初版把"一行 12 个"按 3 段等分（以为每方向连续 4 帧），结果每个方向的 4 帧其实是
  "列组的 3 个方向 + 下一列组的第 1 个方向"——**方向全被打乱**（表现为一段动画里人物朝向乱跳）。
  正确切法是「以列组为单位、组内第 k 个角色对应 dirs[k]」。
- 验证帧序的方法：逐帧算相邻帧差分，`最大/均值` 应接近 1（实测 1.3~2.2）；
  再导 GIF / 帧条看是否同一朝向、动作是否连续。

| 项 | 实测 |
|---|---|
| 朝向覆盖 | 8 向全在（每向 11~12 帧） |
| 单帧身高 | 152~224px，跨视角不齐，入库前按本体身高归一到 104px |
| 画布/网格 | 4736×2688 自由拼图，**不符合** 768×320 / 4×2 / 192×160 规格 → 需切图工序 |
| 攻击刀光 | 白/淡蓝微光（蓝紫分量远高于红），**未加** ANIMATION_SPEC §1 规定的红色系红闪/暗红弧光 |
| 受击/闪避 | 动作向（受击后仰、闪避贴地低姿）成立，闪避帧身高压到 155px 左右属压低姿态，正常 |

### A.2.1 切图工序（已完成，可复用）

工具：`tools/slice_new_moves.py`（依赖 PIL；本机用 `.../python/versions/3.14.3/python.exe`，3.13 未装 PIL）

流程：按行组/子行的方向表定位 → 每行按 alpha 列投影切出角色块 → 顺序等分给各方向
（实测每行恰为「方向数 × 4 帧」，等分比按间隙聚类稳）→ 归一化到游戏规格。

归一化关键点：**身高与锚点只按"深色像素"（黑衣本体）量**，特效不计入——
攻击帧带大刀光弧，若按整块 alpha 包围盒归一，弧光会撑大身高、角色被缩成小人（已修）。
输出：裁切 → 缩放到本体身高 104px → 脚底贴 `y=144` → 本体头顶带中线贴 `x=96` → 192×160 格。

产物：
- `.tmp_preview/new_moves/sliced/<动作>/<方向>_<序号>.png` —— 8 向 × 11~12 帧/动作，已是游戏规格单帧
- `.tmp_preview/new_moves/review_<动作>_<方向>.png` —— 每方向一条帧条，供人工核对
- `.tmp_preview/new_moves/slice_report.txt` —— 帧数/身高/出格统计

已知问题：已解决（见 A.2.2）。

**重跑方式**：`python tools/package_new_moves_v2.py`（切图+对齐）→ `godot --headless --path . --import`（导入）

→ `godot --headless --path . --script res://tools/validate_new_player_frames.gd`（校验）

**脚本踩过的三个坑（重跑时注意）**

1. 定位本体必须用**深色像素**：攻击/闪避帧的大亮色刀光弧会让 alpha 行带糊成一片。
2. 同一个方向的 4 帧在 sheet 上**分散在不同 x**（每个角色块是独立图源）→ 必须**逐帧**按各自头顶
   中线对齐，不能用"整段统一偏移"（用统一偏移会把画布撑到 1400px 宽）。
3. 躺倒/迈步姿势会越出子行范围 → 本体框必须取自**连通域**而不是子行矩形，否则锚点偏高、
   帧底被裁（death 曾偏差 16px）。

### A.3 即时野战（8 方向）缺口

方向覆盖已够、切图已完成（见 A.2.1），剩余缺口只有**状态**：

| 状态 | 新版已有 | 野战还缺 |
|---|---|---|
| 移动（跑）/ 攻击 / 受击 / 闪避 | ✓ 8 向 × 11~12 帧 | 打包成图集 + SpriteFrames、定 fps |
| **待机 idle** | ✗ | **必须有**（站立是最高频状态，缺了跑图时会一直跑步动） |
| **死亡 death** | ✗ | **必须有**（野战会阵亡） |
| 格挡 guard | ✗ | 野战不要（归回合制指令）；回合制要单方向 |
| 蓄力战技斩铁 | ✗ | 可复用攻击帧 + 程序化特效 |

打包待定项：① 循环 fps（11~12 帧若塞进现有 0.8s 片长 ≈ 15fps，或抽到 8 帧保持 10fps）；
② 攻击 left/right 的超格刀光是否放宽格子；③ 是否沿用 `player_frames.tres` 的自动生成方式。

### A.4 两条路线的美术结论

既然新 sheet 已含 8 方向，两条路线的美术代价都落到"补 idle + death + 切图"上：

| 路线 | 额外绘制 | 额外工序 |
|---|---|---|
| D1a 8 方向即时野战 | idle、death（8 方向版） | 四张 sheet 切图（已完成，见 A.2.1）+ 打包图集 |
| D1b 接触即战纯回合 | idle、death（单方向版，各 8 帧） | 只切战斗演出用的一组视角 |

差别不在于"画多少方向"，而在于：**8 方向路线要求 idle / death 也出全 8 向**（否则站立和倒地会缺角度），
且以后每加一个战技都要考虑 8 向覆盖；回合制路线把后续技能的表现全部交给特效层，永不增加方向成本。
