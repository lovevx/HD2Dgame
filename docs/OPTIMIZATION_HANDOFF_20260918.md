# Demo 优化交接清单（2026-09-18）

## 范围与现状

当前可玩链路为契约开场 → 废品终点站 → 王都入口 → 侍卫总部 → 欢乐街 → 科尔波山外围与巨虎 → 阶段结算 → 灰潮港整备 → 再次出发。原著国王主线并未完成，阶段结算只代表这个 Demo 的结束。继续沿用已有场景、预置素材、角色和音效；本清单不要求建新场景、建模或生成图片。

本轮在工作区已有的未提交关卡细化上做了四项优化：四关入口改为不遮挡战斗的地面标记；HUD 的目标、消息、操作提示和剧情条改为按边缘定位，目标增加暗底；王都入口与侍卫总部的出口读取引荐信、斩龙闪的真实推进条件，HUD 写明缺少的操作；巨虎战必须通过返回门结算，清场后任意位置按 V 只给导航提示。`CORE_LOOP_PLAYTEST.md` 的传送操作说明已同步。已有未提交的关卡布景、人形敌人和剧情文字仍属于原工作区改动，后续 Agent 应先看 `git diff`，不要直接覆盖。

验证：Godot 4.7.2 的 `tools/validate_level_refine.gd` 在无头与 D3D12 实渲染均为 `LEVEL_REFINE_FAILURES=0`；`tools/validate_core_loop.gd` 为 `CORE_LOOP_FAILURES=0`。这些脚本主要验证流程与状态，不能替代真实玩家的难度、导航和操作手感测试。

## 已知边界与协作顺序

- 当前四个前段地区仍共用原练习场地面和活动边界，布景只是使用既有预置的装饰。要提升地区感，先调整这些预置的摆位、镜头焦点、灯光和材质参数；不要把背景装饰当作真实掩体来设计战术。
- 现有自动验收使用伤害接口快速击败敌人，未测鼠标瞄准、闪避时机、路标识别和长时间性能。下一位 Agent 应先人工试玩并记录问题，再按上表逐项修改，每项跑相应验证脚本。
- `docs/NOVEL_VOL1_LEVELS.md` 限定当前剧情止于猎虎；`docs/NOVEL_CORE_SYSTEMS.md` 和 `docs/P1_SCOPE_BASELINE.md` 记录原著规则与已确定的游戏化取舍。调整 UI 文案时沿用“乐园/烙印/契约者/世界之源”等现有术语，不把后续国王剧情或灭法之影能力写成已解锁。
- 每次改动前确认工作区已有未提交文件的作者和内容；优先在当前文件上小范围修改，不重跑会覆盖场景的生成脚本。
