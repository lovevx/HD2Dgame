# 0. 总览

## 0.1 一句话与三条支柱

**用"读招—取舍—兑现"的近战刀战，把法力和站位变成真正的资源，而不是让玩家站桩换血。**

承接 GDD §1 的四支柱，落到战斗层：

| 支柱 | 战斗层的具体要求 | 反面（出现即视为设计失败） |
|---|---|---|
| **技法优先** | 敌人的大伤害攻击必须有可辨前摇；闪避/走位能实质降低风险；属性不能买断风险 | 靠堆数值无视预警硬吃；看不清攻击来源就掉血 |
| **资源博弈** | 法力是核心资源，持续消耗（猎魔）与瞬时爆发（刀术）互斥；HP 与护甲耐久是第二层预算 | 法力长期满格无出口；护甲耐久只涨不扣 |
| **节奏切换** | 即时战斗负责"侦察—消耗—攒破绽"，回合制负责"兑现—控场—付出代价"；两种节奏各有存在理由 | 任一形态变成纯过场；玩家想跳过回合制 |

## 0.2 两形态分工

| | **即时战斗**（原"形态 A / 即时野战"） | **回合制战斗**（原"形态 B / 回合指令战"） |
|---|---|---|
| 定位 | 探索期遭遇、消耗、攒破绽；**全部小怪战都在这里打完** | 兑现战果、决战**科尔波山之主**、控场取舍 |
| 谁打 | 小怪（除科尔波山之主外的全部敌人，含具名强敌） | 只有**科尔波山之主**（唯一触发者，见 §2.2） |
| 操作 | WASD + 鼠标 + 技能键（实时） | 移动力步进 + 三选一指令（回合） |
| 时长目标 | 单次遭遇 10~40 秒 | **山之主战分期推进**（P1/P2/P3 三阶段，逐步加压） |
| 演出 | 8 方向帧（现有素材复用） | 复用现有帧，**零新增美术** |
| 现状 | `✅已定` 已实装，战役主线现行玩法 | `✅已定` P1 已实装，**仅练习/试炼场**；战役未接 |

> **为什么必须要有回合制**（成本理由，别忘）：原实时动作战斗的帧成本是 **每动作 8 方向 × 5 镜 3 ≈ 40 帧**，已出现"环断复用三段挥刀帧、傲歌复用防御姿态、影刺无动画"的妥协。回合制把战斗演出压到**复用现有帧 + 程序化特效**，新技能**永不新增帧序列**。`✅已定`：这是本改版的第一目标，不是玩法偏好。

## 0.3 两形态的衔接

```
探索（八方向行走 / 轨道镜头 / 港口与关卡，全部不变）
  │
  ▼ 遭遇敌人（在场地里直接开打，无独立"入战圈"）
┌─ 即时战斗（小怪）─────────────────────────────────┐
│  平A / 直踹 / 环断 + 基础操作（移动 · 剃）        │
│  命中 → 敌人眩晕条（0~100）                       │
│  眩晕条满 → 停止移动                              │
│      → 用【直踹】命中 = 处决击杀                   │
└───────────────────────────────────────────────────┘
┌─ 即时战斗（科尔波山之主）─────────────────────────┐
│  同样用平A / 直踹 / 环断 积攒眩晕                  │
│  眩晕条满 → 玩家"再次攻击命中" ⇒ 进入回合制         │
└───────────────────┬───────────────────────────────┘
                    ▼
┌─ 回合制战斗（**不切场景**，原地进入）─────────────┐
│  ① 进入演出：拉近摄像机 + 播放触发的那次攻击动画     │
│  ② 我方获得 1 回合先手权                          │
│  指令五条：攻击 / 战技 / 防御 / 道具 / 逃跑       │
│  敌人回合：接近 → 攻击（或按阶段放技能）            │
│  胜利 → 掉落结算（equipment_drop 现有）           │
└────────────────────────────────────────────────┘
```

## 0.4 跨形态通则

- **状态携带**：HP / MP / 位置 / 已用道具 / 护甲耐久全部**跨形态连续**，不做战斗内重置。
- **门闩成对**：`player.battle_mode` 与 `enemy.battle_driven` 必须成对开关，退出时还原（已实装）。
- **脱离手段**：即时战斗**没有**逃跑（要结束只能打赢或被打死）；**回合制保留「逃跑」指令**（敏捷对抗、成功即退出战斗，无掉落）——`flee()` 有效（`✅已定` 作者 09-23，指令集回到五条）。
- **数值层共用**：两形态的伤害公式、技能倍率、装备与属性全部走同一套数据源（见第三部），形态只改变"何时可用、怎么结算"。

## 0.5 非目标（本期明确不做）

- **不做战斗圈 / 结界 / 禁出**（`✅已定` 作者 09-22：取消"圈内入战"，遭遇即原地开打）。
- **回合指令是五条，含防御与逃跑**（`✅已定` 作者 09-23：指令集回到"攻击 / 战技 / 防御 / 道具 / 逃跑"，见 §2.5）；**拼刀仍然不做**（D3 不变，与防御指令已解绑）。
- **不做"Boss 场无脑强制回合"**：回合必须由玩家**打进眩晕 + 补一刀**主动触发。
- **不做单方向 `battle_idle` / `cast` 新帧**（`✅已定` 作者 09-22：复用现有 `idle` / `attack` 即可）。
- 不做队友 / 连携 / 合击（`✅已定` D5：本版不做，`battle_unit` 仅预留列表接口）。
- 不做 AT 奖励 / 抢夺、魔法吟唱时间、BP 勇气点（`✅已定`，见 TURNBASED_COMBAT_PLAN §2 裁剪表）。
- 不做"被眩晕后处决玩家"——玩家侧永远走 HP 结算（`✅已定`）。
- 不做灵魂伤害的实际技能、敌人与 UI（`✅已定` GDD §5.3：仅保留枚举与规则测试接口）。
- 不做 QTE / 时机条 / 复杂破防条（本期只有眩晕条一种资源条）。

## 0.6 成功判据（可测）

| 判据 | 目标 | 怎么测 |
|---|---|---|
| 战斗理解速度 | 新玩家 5 分钟内理解平A / 剃 / 一个技能 | 观察式试玩（GDD §14） |
| 死亡原因可读 | 主要死亡可归因到"看错招 / 贪刀"，而非"没看清" | 死亡回放问询 |

| 法力有张力 | 一局中至少一次因法力不足放弃猎魔 / 技能 | 试玩观察 |

# 第一部　即时战斗

## 1.1 定位

- **承载全部小怪战**：从 1.2 废品终点站的持械流民，到 1.5 欢乐街的欧卡与护卫，都在即时战斗中打完。
- **为回合制做前置**：对山之主战时，即时战斗的职责是"把眩晕条打满"，再由玩家补一刀把战斗推进到回合制。
- **手感不推翻**：探索与走位（八方向行走、轨道镜头、港口与关卡场景）**全部不动**（`✅已定`）；伤害数值也维持现值，不做轨迹式"刮痧"惩罚——小怪本来 1~2 刀死。

## 1.2 可用动作集（`✅已定`：作者 09-22 确认「平A / 直踹 / 环断 + 基础操作」）

| 动作 | 键 | 作用 | 现值 |
|---|---|---|---|
| **平A**（单段斜劈） | 左键 | 主要输出 / 攒眩晕 | 1.3× 面板，CD 0.6s，命中帧 0.12s，reach 2.5，弧半角 1.0 rad |
| **直踹** | K | 高眩晕值技，负责把敌人打进眩晕；也是**处决**手段 | MP 8，CD 0.9s，倍率 1.0，reach 2.8，弧 0.35，`📝提案` 眩晕 +25 |
| **环断** | F | 清环绕的多目标 | 1.2×，MP 24，CD 4.5s，半径 4.2 + 目标 bulk |
| 移动 / 奔跑 | WASD | 走位（常驻跑步） | 2.6 + (敏捷−5)×0.026 |
| 剃（六式・剃） | Space | 位移 + 无敌帧规避（基础操作） | 蓄力 0.15s（**仅此段无敌**）→ 爆发 0.32s → 落地 0.08s，CD 2.2s，位移 ≈6.6 m |
| 燧发枪 | 右键 | 远程消耗（逼敌耗能） | 2~13 双 roll × 力量倍率，弹药 6，射速 1.8s → **是否留在即时战斗待确认**（Q6） |

> **命名**：本技能在既有文档与代码注释中写作「直踢」（`_start_kick` / `KICK_*`），与「直踹」为同一技能；本文统一用**直踹**，代码常量名不改。

**本形态封版（`✅已定`）**：即时战斗的攻击手段就是**平A + 直踹 + 环断**，加上移动 / 剃等基础操作。

| 不在本形态 | 去向 |
|---|---|
| 刀芒（剑气·断空）R | 移入回合制「技能」子页；R 键空出（Q6） |
| 影刺 T | 移入回合制「技能」子页；取消"先手标记"前置 |
| 使徒之眼 / 吞噬之核 | `✅已定` 后置（DEFERRED） |

## 1.3 手感契约（`✅已定` GDD §5.2，改动需慎重）

- 动作分为**前摇 / 有效帧 / 后摇**；判定由动作时间轴驱动，**不由帧率决定**。
- 单次攻击分配 `attack_id`，同一目标仅被该次攻击命中一次。
- 输入缓冲 0.15s；朝向在**前摇开始后锁定**，移动不能覆盖攻击方向。
- 攻击方向 = 鼠标点击点投影到战斗平面的方向；点 UI 不出手；点脚下导致方向过短时沿用上次有效方向。
- 轻敌可打断、重甲具韧性、山之主仅在指定破绽可打断；禁止平A 无限硬直。

# 第二部　回合制战斗

## 2.1 定位

- **只有一场**：决战**科尔波山之主**（1.6 科尔波山）。它是玩家在即时战斗里"把山之主打进眩晕 + 补一刀"主动打出来的奖励段落。
- **不切场景**：原地开打，不做独立战斗场景、不做入战圈。
- **对手只有 1 个**，所以本形态当前实际是 **1v1**——AT 顺序条与多单位逻辑暂时没有第二个用户（详见 §2.4 的推论）。

## 2.2 进入条件与进入演出（`✅已定`：作者 09-22）

| 项 | 规定 | 状态 |
|---|---|---|
| **触发** | **科尔波山之主**眩晕后，玩家**再次攻击命中** | `✅已定 已实装`（`player.struck_stunned_foe` 信号 → 场景接管） |
| **进入演出** | **不新增美术**：**拉近摄像机 + 播放触发它的那次攻击的现有动画** | `✅已定`（作者 09-22 第二轮） |
| **先手权** | 进入后我方获得 **1 回合先手权** | `✅已定` |
| **不做"圈内入战"** | 没有战斗圈半径、没有结界网格、没有禁出限制 —— 原 `encounter_zone.gd` 方案**作废** | `✅已定` |
| **不做"Boss 场强制回合"** | 回合由"打进眩晕 + 补一刀"**主动触发**，原 `force_turn_battle` 强制标记方案作废 | `✅已定` |
| 场景 | **不切场景**，原地进入；站位不重排 | `✅已定`；`⚑待定` 是否需要"拉开距离"的演出位移 → Q8 |

**进入演出的时序**：

```
拉近摄像机（缓动）+ 播放「触发它的那次攻击」的现有动画
        ↓ 动画结束、镜头到位
   我方先手，进入第 1 回合指令
```

> **为什么不做禁出结界**：回合制是被玩家**打出来的奖励段落**，不是地形陷阱。把玩家关进圈里既要额外美术（结界网格），又与"不切场景、不加美术成本"的改版初衷相悖；同时"禁出"还会引出"敌人是否同受限制"这类没有收益的边界问题。
>
> **进入演出的成本为零**：现有帧表（8 方向 × 12 帧）已含 `attack` / `kick` 两套攻击动作，8 向齐全——直接播触发攻击对应的那一套即可，不需要任何新绘制。

## 2.3 战斗镜头（`✅已定` 做法；参数 `⚑待定`）

- `✅已定`（作者 09-22）：进入时**相机拉近并固定**；退出后恢复玩家的轨道视角与参数。
- **理由**：回合内的侧 / 背击加成需要**稳定视角**才能读朝向；自由轨道会让玩家转出有利角度白嫖加成。
- `⚑待定`：具体视角参数（俯角 / 距离 / 取景构图 / 缓动时长）——**作者后续补参考图**（Q8）。参考图到位前，实现层先用"从当前机位拉近 + `camera_orbit_controls.enabled = false` 锁定"占位。
- ⚠️ 代码现状：`main.gd::start_battle()` **尚未触碰** `camera_orbit_controls`，运镜与进入演出均**未实装**，P2 补。

## 2.4 回合结构：AT 与行动（`✅已定`，多数已实装）

| 项 | 值 |
|---|---|
| **第 1 回合先手** | 进入时**我方必定先手 1 回合**（进入奖励，见 §2.2）；从第 2 轮起按敏捷降序。`✅已定 已实装`：`BattleController.begin_battle_with_player_first()` |
| 先攻排序 | 敏捷降序；**敏捷相同时玩家先手** |
| 玩家先攻值 | 玩家 = 敏捷；敌人 = 基线 5 |
| 一轮 | 序列内每个单位各行动一次 → 重排 + 结算回蓝 |
| 我方回合 | 先自动走位 `min(移动力, 距离 − 攻击距离)` → 再出一**条**指令 |
| 移动力 | 玩家 `3.0 + (敏捷 − 5) × 0.2` m；敌人 = `move_speed` |
| AT 奖励 / 抢夺 | 不做 |

> **设计意图**：敏捷在本作**只改移速与先攻**（`✅已定` GDD §6：P1 不改攻速 / 缓冲 / 闪避时长），所以先攻是它唯一的战斗收益——这是"给敏捷开第二条用途"的落点。
>
> ✅ **代码现状**：首轮先手**已实装**（`begin_battle_with_player_first()` 把玩家单位挪到本轮序列首位）；`_rebuild_order()` 仍只做敏捷降序，所以**第 2 轮起**回到正常顺序。
>
> ⚠️ **一个重要推论**：回合制目前**只服务"玩家 vs 山之主"这一场 1v1**——1.6 的敌人表是空的（`data/campaign.gd`：`"enemies": []`，场上只有山之主本体 + 开局发的 3 颗炸弹）。于是 AT 顺序条、多单位轮转、`nearest_foe_to()` 这些逻辑**暂时没有第二个用户**。这不影响实施，但决定了两件事：
> 1. **先保证 1v1 的体验**（意图预告、镜头拉近、进入演出），不要为多单位场景提前加复杂度；
> 2. AT 与多单位逻辑要等"出现第二个 Boss 档敌人"或"山之主 + 召唤物"时才真正被验证——**那时再回来审这一节**（Q2）。

## 2.6 站位与侧 / 背击（`✅已定`，已实装）

| 关系 | 判定 | 乘数 |
|---|---|---|
| 正面 | `dot(目标朝向, 目标→攻击者) > 0.7` | ×1.0 |
| 侧击 | 其余 | **×1.1** |
| 背击 | `< −0.45` | **×1.25** |

> ⚠️ **09-23 修正**：判定必须读**目标自己的朝向**。旧实现拿**攻击者**朝向去点乘"攻击者→目标"，而出事前 `_face()` 刚把攻击者拧向目标 —— 两者同向、点乘恒为 1，**永远落进正面分支**，侧 / 背击加成实际不可达（旧注释写的是"目标→我"，代码不是）。现按目标朝向判定：玩家读 `facing` 字段，敌人读 `−basis.z`（敌人只 lerp `rotation.y`，没有 `facing`）。
>
> 另需注意：1v1 回合战里敌人会转身面向玩家，所以修好之后**大多数攻击仍会判定为正面** —— 区别是这成了"判定结果"，而不是"写死的常数"。多单位 / 侧翼场景出现前，背击的可玩性收益有限（Q2）。

## 3.2 伤害与受击链

**我方输出链**

```text
物理伤害 = 双 roll 取平均(武器强化后区间) × 裸装力量倍率 str_atk_coef(力量) × (1 + 0.1 × 刀术训练) × 技能倍率
武器损毁时 roll × 0.5
真实伤害（猎魔 / 影刺）为加法附加：不进倍率、跳过敌人物理减免；护盾照常吸收。
```

**我方受击链**（`✅已定`）

```text
原始伤害 × (1 − 护甲总减免，各槽 def_pct 求和 clamp 0~0.9) × 肉体修正 con_hit_factor(体力)
↓ 傲歌护盾吸收（先吸盾，余量扣 HP；破盾即碎）
↓ 扣 HP ≤ 0 → 死亡（清标记、闭猎魔、碎盾）
↓ 护甲耐久：实际扣血折算，一次命中只扣一件未损毁护甲
```

- `✅已定` 真伤只对 `has_energy == true` 的敌人生效；纯肉体敌人只吃物理伤害。
- `⚑待定` 真实抗性 / 灵魂抗性本期不参与（GDD §5.3：仅保留枚举与测试接口）。
- 山之主这类大体积目标带判定半径（`hit_radius()`），否则要贴到身体中心才能打到。
