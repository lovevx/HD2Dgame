# 六维属性系统实现

## 背景（Context）

《轮回乐园》同人 HD-2D 项目目前的角色数值是硬编码导出字段（player.gd 里 `max_hp=100`、`attack_damage=16`、`move_speed=5.0`、MP 常量 100），没有任何属性维度的数据结构。设计文档（GDD.md 第 6 节、NOVEL_CORE_SYSTEMS.md 第 2 节、SKILL_NUMERICS_SUXIAO.md 基础常量）已定义六维属性体系，本次把它落成代码：六维字段 + 存档持久化、四维生效（力量→攻击、体力→HP、智力→MP、敏捷→移速），魅力/幸运只存档不参与公式；并在 Esc 菜单里加一块「角色属性」卡片直观显示六维与派生值，提供属性点分配与测试发放入口。

用户已确认口径：**起始六维统一 5**（攻击将变为 7+5=12，MP 上限 50，现有战斗会变慢属预期）。

## 数值口径（本次落地）

| 属性 | 公式 | 初始（六维=5） |
|---|---|---|
| 力量 | 攻击 = 武器基础 7 + 力量 | 12 |
| 敏捷 | 移速 = 5.0 + (敏捷-5)×0.05（待校准） | 5.0 |
| 体力 | 最大 HP = 50 + 体力×10 | 100 |
| 智力 | 最大 MP = 智力×10 | 50 |
| 魅力 / 幸运 | 仅存档字段，不参与任何公式 | 5 / 5 |

- 可投入属性点的维度仅 **力量/敏捷/体力/智力**；魅力、幸运锁定为 0 成长（GDD 首版约束）。
- 属性点池 `attr_points` 持久化；20 源点兑换 1 点的经济结算在 B04 之后接入，本次先留 `spend_attr_point()` 接口 + 测试发放入口。
- MP 相关：player 现硬编码 `mp=100` 常量与恢复上限、HUD「MP %d / 100」全部改为派生 `max_mp`。

## 改动清单

### 1. 新建 `data/attributes.gd`（class_name Attributes，纯静态数据表）
单一事实来源，防止公式散落各处被改写：
- 常量：`BASE=5`、`WEAPON_BASE_ATK=7`、`SPENDABLE=["str","agi","con","int"]`。
- 静态方法：`defaults() -> Dictionary`、`max_hp(a)`、`max_mp(a)`、`attack(a)`、`move_speed(a)`、`is_spendable(key)`。
- 键名统一用 `"str"/"agi"/"con"/"int"/"cha"/"luk"`（魅力 cha、幸运 luk），避免中文键在 ConfigFile/序列化中的坑。

### 2. `autoload/game_state.gd`（属性状态 + 持久化）
- 新增字段：`attributes: Dictionary`（init 为 `Attributes.defaults()`）、`attr_points: int = 0`。
- 新增信号：`attributes_changed`（HUD 与 player 刷新用）。
- 新 API：
  - `get_attribute(key) -> int`、`get_attr_points() -> int`
  - `spend_attr_point(key, delta=1) -> bool`：校验 `Attributes.is_spendable && attr_points ≥ 1`，成功则改值、扣点、落盘、发信号。
  - `grant_attr_points(n)`：测试发放（后续被 20 源点兑换取代），同样落盘。
- `save_game()/load_game()`：在 `progress` 段新增 `attributes`（存 Dictionary）与 `attr_points` 两个键；读取时用 `Attributes.defaults()` 兜底合并，防旧档缺字段。
- `reset_progress()`：清空时把 `attributes` 重置为默认 5、`attr_points=0`。

### 3. `player.gd`（四维接线）
- 新增 `var max_mp: float`；`reset()` 开头调用派生刷新：`max_hp = Attributes.max_hp(gs.attributes)`、`max_mp = Attributes.max_mp(...)`、`attack_damage = Attributes.attack(...)`、`move_speed = Attributes.move_speed(...)`，随后 `hp = max_hp`、`mp = max_mp`。
- 替换硬编码 100：`reset()` 里 `mp = 100.0` → `mp = max_mp`；MP 自然恢复 `clampf(mp + 12*delta, 0, 100)` → 上限 `max_mp`。
- 监听 `GameState.attributes_changed`：在树内时重新算派生值（当前 hp/mp 用 `minf` 收进新上限），让面板分配后立即生效。
- 保留现有 `@export` 字段作编辑器默认值；运行期以 GameState 派生值为准。
- 不用动：combo/拼刀/剃/炸弹/药剂逻辑。

### 4. `scripts/ui/hud.gd`（属性卡片）
- `_process` 的 stats 文案：`"MP %d / %d" % [player.mp, player.max_mp]`（替换硬编码 /100）。
- `_build_menu` 的 Esc 卡片里加「角色属性」区块（复用 `_label`/`_card_style`）：
  - 六维六行：力量/敏捷/体力/智力/魅力/幸运 + 数值；第二行派生值：攻击 / 最大HP / 最大MP / 移速；末尾标「剩余属性点 N」。
  - 每场打开菜单时刷新（连接 `GameState.attributes_changed`），点数>0 时给 str/agi/con/int 各渲染「+1」按钮调 `GameState.spend_attr_point`；点数=0 时只显示数值。
  - 底部小号灰字按钮「测试 · +5 属性点」→ `GameState.grant_attr_points(5)`（P1 调试入口，后续由 20 源点兑换替换）。
- 菜单卡片 `mouse_filter` 已是 STOP，点按钮不会误触发攻击。

### 5. 文档同步 `docs/SKILL_NUMERICS_SUXIAO.md`
- 基础常量表「基础攻击」设计值改注：起始六维统一 5 → 7+5=**12**，引擎现值同步；最大 MP 现值 100 → 50；备注加一句「六维接入后攻击基线见 GDD 第 6 节」。
- GDD 已写「起始六维暂统一 5」，无需改。

## 验证

1. Godot 命令行无头校验：`godot --headless --script` 跑一个临时校验脚本（或复用 tools/），断言 `Attributes` 派生值与初始六维=5 的对照表一致：攻击 12、HP 100、MP 50、移速 5.0；`spend_attr_point("luk")` 返回 false、`spend_attr_point("str")` 成功且 attr_points 减一。
2. 运行试炼场（scenes/main/main.tscn）：HUD 顶部显示 HP 100/100、MP 50/50；攻击木桩每刀伤害 ≈12；Esc 打开菜单看到六维数字、派生值、「剩余属性点 0」。
3. 点「测试 · +5 属性点」→ 剩余 5 点，力量行出现「+1」，连点两次 → 力量 7、剩余 3；关闭菜单攻击木桩伤害变 ≈14；移动/HP/MP 数值符合对照表。
4. 退出重进（关窗兜底存档 / main 重进）：属性值与点数保留；主菜单「开始新游戏」reset 后恢复六维 5、点数 0。
